### EC2 へデプロイするときに問題になりそうな点（作業はしていない。対応は要相談）
1. **React のビルドが本番の手順にない**：`compose.prod.yml` は frontend を `npm run dev`（開発サーバー、5173番を外に公開）で起動している。本番では `npm run build` で `frontend/dist` を作ってから `collectstatic` する手順が必要。dist がないと、プレイ画面は試作の `plays/templates/index.html` が表示されて動かない。開発サーバーの5173番を本番で公開するのも避けたい。
2. **アップロード画像（/media/）が配信されない**：DEBUG=False では Django は /media/ を配信しない。nginx に `location /media/` と、`kataruAI/media` を nginx コンテナにマウントする設定が必要。
3. **nginx のアップロード上限**：nginx の初期値は 1MB（`client_max_body_size`）なので、2MB までの画像を送ると 413 エラーになる。`client_max_body_size 3m;` などが必要。
4. **`.env.prod` に必要な値**：`GEMINI_API_KEY`（必須）。`DJANGO_DEBUG` は書かない（書かなければ False）。`DJANGO_ALLOWED_HOSTS` に Elastic IP（やドメイン）を入れる。
5. **gunicorn のワーカー数**：`--workers 2`（同期）。Gemini の応答待ち（最大25秒）の間はワーカーがふさがるので、同時に3人以上がプレイすると待たされる。発表の人数次第で `--workers` を増やすか `--threads` を付ける。
6. **HTTPS にする場合**：`CSRF_TRUSTED_ORIGINS`・`SESSION_COOKIE_SECURE`・`CSRF_COOKIE_SECURE` の設定が必要（今の HTTP・同じオリジンのままなら不要）。
7. **ディスク容量（6.7GB）**：本番で node の開発コンテナを動かすと容量を使う。ビルドだけして止めるか、ビルド済みの dist を持っていく方法にしたい。
8. マイグレーションは `entrypoint.sh` の `migrate --noinput` で起動時に自動で入る（今回の 0002・0003 も自動で入る）。
